## 一、项目总览

### 1.1 分层架构

```
┌──────────────────────────────────────────────────────────────┐
│  浏览器 (static/)                                             │
│  index.html → app.js → api.js / charts.js / map.js / ...      │
└───────────────────────────┬──────────────────────────────────┘
                            │  HTTP (JSON / PNG / CSV / NetCDF)
┌───────────────────────────▼──────────────────────────────────┐
│  接口层 (app/api/)                                            │
│  endpoints/  ← 路由、参数校验、响应组装                        │
│  schemas.py  ← Pydantic 请求体模型                            │
│  deps.py     ← 依赖注入：打开数据集、抽取序列、推断步长         │
└───────────────────────────┬──────────────────────────────────┘
┌───────────────────────────▼──────────────────────────────────┐
│  业务层 (app/services/)                                       │
│  storage.py      ← 文件仓库（上传/列表/删除）                  │
│  nc_processor.py ← NetCDF 读写、统计、出图、导出               │
│  analysis.py     ← 纯算法（谱/小波/突变/相关/EMD）             │
└───────────────────────────┬──────────────────────────────────┘
┌───────────────────────────▼──────────────────────────────────┐
│  基础设施 (app/core/)                                         │
│  config.py  errors.py  ncutils.py  plotting.py                │
└──────────────────────────────────────────────────────────────┘
```

### 1.2 一次请求的完整链路

以「功率谱分析」为例：

```
前端 app.js: runAnalysis("power-spectrum")
  → api.js: PaleoAPI.powerSpectrum(fileId, body)
  → POST /api/analysis/{file_id}/power-spectrum
  → endpoints/analysis.py: power_spectrum()
      → deps.open_dataset()      打开 NetCDF（依赖注入，请求结束自动关闭）
      → deps.extract_series()    按 Selector 取点位/区域序列
      → deps.estimate_dt()       推断采样步长（日→年自动折算）
      → services/analysis.py: power_spectrum()   纯算法计算
  ← JSON { source, values, stats, frequency, power, threshold, peaks }
  → analysis_view.js: renderSpectrum()  渲染指标卡 + SVG 图表
```

**关键约定**：算法层 `analysis.py` 不接触文件、不接触 HTTP，只接收一维数组，
因此可以脱离 Web 单独调用、单独测试。

### 2.1 各文件夹职责一览

| 文件夹 | 职责 | 不应包含 |
| --- | --- | --- |
| `app/core/` | 跨模块复用的基础设施：配置、异常、工具函数、绘图全局设置 | 业务逻辑、HTTP 路由 |
| `app/api/` | HTTP 协议相关：路由注册、参数校验、依赖注入、响应组装 | 复杂算法、文件读写细节 |
| `app/api/endpoints/` | 按业务域拆分的路由模块，一个文件对应一组 URL 前缀 | 跨域复用逻辑（应下沉到 services） |
| `app/services/` | 业务能力：文件仓库、NetCDF 解析、分析算法 | HTTP 概念（Request/Response/状态码） |
| `static/js/` | 浏览器端模块，每个文件暴露一个全局命名空间对象 | 硬编码后端地址（统一走 `api.js`） |
| `static/data/` | 前端静态数据集（海岸线等），由脚本生成 | 用户数据 |
| `data/` | 运行时数据：示例、上传、缓存、临时 | 源码、脚本 |
| `scripts/` | 一次性/周期性任务，不参与服务运行 | 被 `app/` 导入的模块 |
| `tests/` | 自动化测试 | 测试数据大文件（复用 `data/samples`） |

## 三、后端文件详解

### 3.1 `app/main.py` —— 应用入口

| 名称 | 类型 | 作用 |
| --- | --- | --- |
| `lifespan(app)` | 异步上下文 | 启动时建目录并打印文件数；退出时清理 `data/temp`（**保留**上传数据） |

#### `errors.py`

| 类 | 状态码 | code | 使用场景 |
| --- | --- | --- | --- |
| `PaleoVisError` | 400 | `bad_request` | 基类；也可直接用于 403/400 等自定义场景 |
| `NotFoundError` | 404 | `not_found` | 文件 ID 不存在、文件已被移除 |
| `InvalidFileError` | 400 | `invalid_file` | 后缀不支持、内容为空、超过大小、无法解析 |
| `AnalysisError` | 422 | `analysis_failed` | 序列过短/常量、变量不存在、非网格变量 |

> 约定：业务代码只抛这四类异常，**不要**在 service 里抛 `HTTPException`。

### 3.3 `app/api/` —— 接口层

#### `deps.py`

| 名称 | 作用 |
| --- | --- |
| `open_dataset(file_id)` | 生成器依赖：查记录 → 打开 `NCDataset` → `yield` → `finally` 关闭。**每个请求独立打开** |
| `time_range_of(dataset, start, end)` | 把用户给的起止索引夹取到合法范围 |
| `extract_series(dataset, request)` | 按 `Selector` 决定走点位序列还是区域平均序列 |
| `estimate_dt(dataset, explicit)` | 推断采样步长；20~400 天的间隔自动折算为「年」 |

#### `schemas.py`（Pydantic 请求体）

| 模型 | 字段 | 用于 |
| --- | --- | --- |
| `Selector` | `variable, lat, lon, lat_range, lon_range, start, end, level_index` | 取数基类；经纬度只给一半时自动退回区域 |
| `SeriesRequest` | + `detrend, dt` | 通用时序分析基类 |
| `SpectrumRequest` | + `window`（hann/boxcar） | 功率谱 |
| `WaveletRequest` | + `max_scale`（4~512） | 小波 |
| `PeriodRequest` | + `max_period` | 周期分析 |
| `AbruptRequest` | + `method, window` | 突变检测 |
| `EemdRequest` | + `max_imfs, noise, trials` | EEMD |
| `CrossRequest` | `variable_a, variable_b` + 选取条件 | 交叉谱 / 同文件相关 |
| `CorrelationRequest` | `series_a, series_b, method, max_lag` | 任意两序列相关 |
| `CompareRequest` | `series: dict[str, list], normalize` | 多序列对比 |
| `ExportRequest` | `Selector` + `format`（netcdf/csv） | 子集导出 |

### 3.4 `app/services/` —— 业务层

| 名称 | 作用 |
| --- | --- |
| `FileRecord` | 文件元信息数据类（id/name/size/uploaded_at/source/path/readonly） |

**ID 规则**：

- 上传：`{12 位 hex}__{安全文件名}`，如 `a93bf3c9cf57__vol_PR_10y.nc`
- 示例：`sample-{文件名词干}`，如 `sample-sample_climate`，标记 `readonly=True`

| 方法 | 作用 |
| --- | --- |
| `__init__(path, file_id, name)` | 打开数据集（时间解码失败自动降级为数值轴），识别坐标轴 |

| `_build_time_labels()` | 生成人类可读时间标签 |

| `variable_meta(name)` | 单变量元信息（dtype/shape/dims/units/attrs） |
| `_coord_index_range(values, lo, hi, is_lon)` | 经纬度范围 → 索引区间；0~360 轴自动换算负经度 |
| `_slice_var(...)` | 统一按时间/纬度/经度/层次切片（时间为闭区间） |
| `overview(file_size)` | xarray 风格概览：dimensions/coords/variables/attributes/axes/summary |
| `_axis_payload / _variable_stats` | 坐标轴载荷、变量抽样统计（最多 24 个时次，避免全量读盘） |
| `point_series(...)` | 点位序列（最近邻网格点） |
| `area_mean_series(...)` | 区域平均序列（保留经纬度维，仅丢弃层次等额外维） |
| `mean_field(...)` | 时间平均二维场，自动抽稀到 ≤240×240 |
| `_time_range_labels(...)` | 起止时间标签 |
| `render_map(...)` | matplotlib + cartopy 出图（无 cartopy 时退化为普通坐标轴） |
| `render_series(...)` | 服务端渲染时序曲线 PNG |
| `subset_dataset(...)` | 构造子集 `xr.Dataset` |
| `export_netcdf(...)` | 导出子集 NetCDF（带缓存） |

模块级工具：`_coord_extent`、`_range_of`、`_series_stats`、`_pick_cmap`、
`_extent`、`_cache_key`（参数哈希做文件名）、`_timestamp`。

#### `analysis.py` —— 纯算法层

| 函数 | 算法 | 返回要点 |
| --- | --- | --- |
| `power_spectrum` | 周期图 + Hann 窗 + AR(1) 红噪声阈值 | `frequency, period, power, threshold, peaks` |
| `_red_noise_threshold` | Torrence & Compo (1998) 95% 置信线 | 阈值数组 |
| `wavelet_analysis` | Morlet 连续小波变换 | `power[尺度×时间], global, period, cone` |
| `_manual_cwt` | 无 `morlet2` 时的纯 numpy 回退实现 | 复小波系数 |
| `period_analysis` | 自相关 + Burg 最大熵谱 | `acf, spectrum, peaks` |
| `_burg_psd` | Burg 法 AR 谱估计 | 频率/功率谱 |
| `abrupt_change` | 突变检测调度 | 见下三个 |
| `_mann_kendall` | MK 顺序/逆序统计量 UF/UB | `uf, ub, critical, crossings, trend` |
| `_sliding_t` | 滑动 t 检验 | `t, window, critical, extremes` |
| `_pettitt` | Pettitt 非参数检验 | `index, statistic, p_value` |
| `cross_spectrum` | Welch 互谱 | `coherence, phase, correlation` |
| `eemd_decompose` | 集合经验模态分解（自实现） | `imfs, residue, variance_ratio` |
| `_emd / _sift / _local_extrema` | EMD 内部分解与包络插值 | — |
| `correlation` | Pearson/Spearman/Kendall + 滞后相关 + 线性拟合 | `r, p, r2, lag, fit, scatter` |
| `compare_series` | 多序列标准化 + 相关矩阵 | `curves, matrix, summary` |
| `_prepare / _detrend / _top_periods` | 输入清洗、去趋势、峰提取 | — |

#### `/series` 的预处理参数

`/series` 支持在取数的同时做预处理，参数走 query string：

| 参数 | 取值 | 说明 |
| --- | --- | --- |
| `detrend` | `none` / `linear` / `mean` | 线性去趋势或去均值 |
| `standardize` | `true` / `false` | z-score 标准化 |
| `filter` | `none` / `lowpass` / `highpass` / `bandpass` | Butterworth 零相位滤波（filtfilt） |
| `filter_period_min` | 数值 | 最短周期（低通/带通用） |
| `filter_period_max` | 数值 | 最长周期（高通/带通用） |
| `filter_order` | 1~8 | 滤波器阶数，默认 4 |

返回体在原结构上追加：

| 字段 | 说明 |
| --- | --- |
| `raw_values` | 原始值，供前端叠加对比 |
| `preprocess.applied` | 是否实际执行了处理 |
| `preprocess.steps` | 执行步骤，如 `["去趋势(linear)", "滤波(bandpass)", "标准化(z-score)"]` |
| `preprocess.spec` | 生效的配置 |
| `preprocess.reason` | 未执行时的原因（全缺测、方差为 0 等） |

**处理顺序固定为：去趋势 → 滤波 → 标准化**，与分析接口完全一致。

## 七、关键设计约定

1. **无数据库**：文件即状态。上传文件的元信息存在同目录 sidecar JSON 中，
   列表通过扫描目录重建。优点是零依赖、可直接拷贝；缺点是并发与规模受限。
2. **按请求打开数据集**：`open_dataset` 依赖在请求结束时关闭句柄，避免泄漏；
   代价是同一文件被反复打开（见完善方向中的缓存项）。
3. **算法层与 IO 解耦**：`analysis.py` 只吃一维数组，可脱离 Web 单元测试。
4. **前端零依赖**：不使用 CDN、不需要构建步骤，内网/离线可直接运行。
5. **坐标自动识别**：不强制 CF 规范命名，兼容 `lat/latitude/y`、`lon/longitude/x`、
   `time/date`，并按 `units` 兜底。
6. **显式优于隐式**：指定了不存在的变量直接报 422，不静默换变量。
7. **错误契约**：业务异常统一 `{detail, code}`；4xx 表示用户可修正的问题。

## 八、下一步完善方向

按优先级排列。每条给出「现状 → 问题 → 建议」。

### P0：影响可用性的短板

| # | 方向 | 现状 | 问题 | 建议 |
| --- | --- | --- | --- | --- |
| 1 | **长时间任务异步化** | 分析在请求线程内同步执行 | 大文件 + EEMD/小波 可能数十秒，浏览器超时、无进度 | 引入 `BackgroundTasks` 或 Celery/RQ；改为「提交任务 → 轮询 `/tasks/{id}`」；前端加进度条 |
