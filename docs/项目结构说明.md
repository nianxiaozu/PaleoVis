## 一、项目总览

### 1.1 分层架构

```

│  浏览器 (static/)                                             │
│  index.html → app.js → api.js / charts.js / map.js / ...     │
└───────────────────────────┬──────────────────────────────────┘
                            │  HTTP (JSON / PNG / CSV / NetCDF)
┌───────────────────────────▼──────────────────────────────────┐

```

### 1.2 一次请求的完整链路

以「功率谱分析」为例：

```
前端 app.js: runAnalysis("power-spectrum")
  → state.spectrumBody()            从参数面板收集方法/窗函数/周期范围等
  → api.js: PaleoAPI.powerSpectrum(fileId, body)
  → POST /api/analysis/{file_id}/power-spectrum
  → endpoints/analysis.py: power_spectrum()
      → deps.open_dataset()      打开 NetCDF（依赖注入，请求结束自动关闭）
      → deps.extract_series_preprocessed()  按 Selector 取序列并套用预处理
      → deps.estimate_dt()       推断采样步长（日→年自动折算）
      → services/analysis.py: power_spectrum()
            按 method 分派：periodogram / redfit(WOSA) / mtm(DPSS)
            统一用 AR(1) 红噪声 × 卡方因子算显著阈值
  ← JSON { source, values, stats, frequency, power, threshold, peaks, meta }
  → parameter_panel.js: renderSpectrumPanel()  渲染参数面板
  → analysis_view.js: renderSpectrum()         渲染指标卡 + SVG 图表
```

> 交互约定：点击「功率谱分析 / 小波分析 / 周期分析 / 突变分析 / EEMD / 交叉谱 / 相关性 / 多序列对比」时
> **只渲染参数面板、不发请求**，由用户确认参数后点「应用并计算（重算）」才真正计算；
> 交叉谱、相关性、多序列对比的面板里，每个「数据」是一组「数据文件 + 变量」下拉：
> 侧栏有两个以上文件时可跨文件各选各的，只有一个文件时自动退化为同文件里的两个变量。
> 后端用两条序列的时间坐标求交集，只对公共时次计算（见 `services/time_align.py`）。
> 面板注册见 `app.js` 的 `ANALYSIS_PANELS` 与 `showAnalysisPanel`，面板实现见 `parameter_panel.js`。

**关键约定**：算法层 `analysis.py` 不接触文件、不接触 HTTP，只接收一维数组，
因此可以脱离 Web 单独调用、单独测试。

### 2.1 各文件夹职责一览

| 文件夹 | 职责 | 不应包含 |
| --- | --- | --- |
| `app/core/` | 跨模块复用的基础设施：配置、异常、工具函数、绘图全局设置 | 业务逻辑、HTTP 路由 |
| `app/api/` | HTTP 协议相关：路由注册、参数校验、依赖注入、响应组装 | 复杂算法、文件读写细节 |
| `app/api/endpoints/` | 按业务域拆分的路由模块，一个文件对应一组 URL 前缀 | 跨域复用逻辑（应下沉到 services） |
| `app/services/` | 业务能力：文件仓库、NetCDF 解析、分析算法 | HTTP 概念（Request/Response/状态码） |
| `static/js/` | 浏览器端模块，每个文件暴露一个全局命名空间对象 | 硬编码后端地址（统一走 `api.js`） |
| `static/data/` | 前端静态数据集（海岸线等），由脚本生成 | 用户数据 |
| `data/` | 运行时数据：示例、上传、缓存、临时 | 源码、脚本 |
| `scripts/` | 一次性/周期性任务，不参与服务运行 | 被 `app/` 导入的模块 |
| `tests/` | 自动化测试 | 测试数据大文件（复用 `data/samples`） |

## 三、后端文件详解

### 3.1 `app/main.py` —— 应用入口

| 名称 | 类型 | 作用 |
| --- | --- | --- |
| `lifespan(app)` | 异步上下文 | 启动时建目录并打印文件数；退出时清理 `data/temp`（**保留**上传数据） |

| `validation_error_handler` | 异常处理器 | 把 Pydantic 校验失败转成统一的 `422 validation_error` |
| `health()` | `GET /api/health` | 健康检查，返回状态、版本、文件数 |
| `runtime_config()` | `GET /api/config` | 前端运行配置：项目名、上传上限、允许后缀 |
| `index()` | `GET /` | 返回 `static/index.html`；缺失时回退为 JSON |

同时负责：注册 CORS、挂载 `/static`、`include_router` 三个路由模块。

#### `errors.py`

| 类 | 状态码 | code | 使用场景 |
| --- | --- | --- | --- |
| `PaleoVisError` | 400 | `bad_request` | 基类；也可直接用于 403/400 等自定义场景 |
| `NotFoundError` | 404 | `not_found` | 文件 ID 不存在、文件已被移除 |
| `InvalidFileError` | 400 | `invalid_file` | 后缀不支持、内容为空、超过大小、无法解析 |
| `AnalysisError` | 422 | `analysis_failed` | 序列过短/常量、变量不存在、非网格变量 |

> 约定：业务代码只抛这四类异常，**不要**在 service 里抛 `HTTPException`。

### 3.3 `app/api/` —— 接口层

#### `deps.py`

| 名称 | 作用 |
| --- | --- |
| `open_dataset(file_id)` | 生成器依赖：查记录 → 打开 `NCDataset` → `yield` → `finally` 关闭。**每个请求独立打开** |
| `time_range_of(dataset, start, end)` | 把用户给的起止索引夹取到合法范围 |
| `extract_series(dataset, request)` | 按 `Selector` 决定走点位序列还是区域平均序列 |
| `extract_series_preprocessed(dataset, request)` | 在上一步基础上套用 `request.preprocess`，并把 `preprocess` 说明回填到返回体 |
| `_stats(values)` | 统一统计量（n/min/max/mean/std/median/nan_count） |
| `estimate_dt(dataset, explicit)` | 推断采样步长；20~400 天的间隔自动折算为「年」 |

#### `schemas.py`（Pydantic 请求体）

| 模型 | 字段 | 用于 |
| --- | --- | --- |
| `Selector` | `variable, lat, lon, lat_range, lon_range, start, end, level_index` | 取数基类；经纬度只给一半时自动退回区域 |
| `SeriesRequest` | + `detrend, dt` | 通用时序分析基类 |
| `SpectrumRequest` | + `method, window, min_periods, max_periods, ofac, hifac, n50, iwin, nw, k, confidence` | 功率谱（三种方法共用） |
| `PreprocessSpec` | `detrend, standardize, filter, filter_period_min/max, order` | 序列预处理（内嵌于 `SeriesRequest`） |
| `WaveletRequest` | + `max_scale`（4~512）, `confidence`, `pad`, `dj`, `j1_n_div_dj`, `s0`, `lag1`, `mother`, `mother_param`, `sigtest_wavelet`, `sigtest_global` | 小波（后 9 个直接透传给 easyclimate） |
| `PeriodRequest` | + `max_period, confidence, max_lag, order` | 周期分析 |
| `AbruptRequest` | + `method, window` | 突变检测 |
| `EemdRequest` | + `max_imfs, noise, trials` | EEMD |
| `CrossFileRequest` | `file_a, file_b, variable_a, variable_b` + `area_method` + 选取条件 + `method, max_lag, normalize, detrend` | 交叉谱 / 相关性 / 多序列对比（可跨文件） |
| `CorrelationRequest` | `series_a, series_b, method, max_lag` | 任意两序列相关（脚本调用） |
| `CompareRequest` | `series: dict[str, list], normalize` | 任意多序列对比（脚本调用） |
| `ExportRequest` | `Selector` + `format`（netcdf/csv） | 子集导出 |

### 3.4 `app/services/` —— 业务层

#### `storage.py`

| 名称 | 作用 |
| --- | --- |
| `FileRecord` | 文件元信息数据类（id/name/size/uploaded_at/source/path/readonly） |
| `FileRecord.public()` | 对外序列化（剔除服务器路径） |
| `_safe_filename(name)` | 清洗文件名，保留中文/字母/数字/.\_-，限制 80 字符 |
| `StorageService.list_records()` | 合并 `uploads/` 与 `samples/`，按时间倒序 |
| `StorageService.get(file_id)` | 按 ID 查记录，不存在抛 `NotFoundError` |
| `StorageService.path_of(file_id)` | 取磁盘路径并校验存在 |
| `StorageService.save_upload(name, bytes)` | 小文件整块写入（保留给内部调用） |
| `StorageService.save_stream(name, stream)` | **主上传通道**：1 MB 分块写入，超限即删并报错 |
| `StorageService.delete(file_id)` | 删除上传文件 + sidecar；示例数据抛 403；校验路径必须位于 `uploads/` 内 |
| `StorageService.clear_cache()` | 清空 `cache/` 并重建 |
| `_write_sidecar / _sidecar_path` | 每个上传文件旁的 `{id}.json` 元信息 |
| `_scan_uploads / _scan_samples` | 扫描磁盘重建记录（无数据库） |

**ID 规则**：

- 上传：`{12 位 hex}__{安全文件名}`，如 `a93bf3c9cf57__vol_PR_10y.nc`
- 示例：`sample-{文件名词干}`，如 `sample-sample_climate`，标记 `readonly=True`

#### `nc_processor.py` —— `NCDataset` 类

| 方法 | 作用 |
| --- | --- |
| `__init__(path, file_id, name)` | 打开数据集（时间解码失败自动降级为数值轴），识别坐标轴 |
| `close()` / `__enter__` / `__exit__` | 资源释放，支持 `with` |
| `_detect_axes()` | 识别 lat/lon/time/level 坐标名与取值 |
| `_coord_values(name)` | 安全读取坐标数组（缺失返回空数组） |
| `_build_time_labels()` | 生成人类可读时间标签 |
| `resolve_variable(name)` | 解析变量名；**显式指定但不存在时直接报错**，不静默回退 |
| `variable_meta(name)` | 单变量元信息（dtype/shape/dims/units/attrs） |
| `_coord_index_range(values, lo, hi, is_lon)` | 经纬度范围 → 索引区间；0~360 轴自动换算负经度 |
| `_slice_var(...)` | 统一按时间/纬度/经度/层次切片（时间为闭区间） |
| `overview(file_size)` | xarray 风格概览：dimensions/coords/variables/attributes/axes/layout/summary |
| `hovmoller_field(...)` | 时间 × 纬度（或经度）的 Hovmöller 场 |

| 参数 | 取值 | 说明 |

#### `/power-spectrum` 的三种计算方法

| `method` | 算法 | 用到的参数 | 自由度 / 带宽 |
| --- | --- | --- | --- |
| `periodogram` | 经典周期图，**调用 easyclimate `filter.spectrum.calc_time_spectrum`**；先乘窗函数，再把 `\|ifft\|²` 换算成谱密度 | `window`（none/boxcar/hann/hamming/blackman/bartlett） | `dof=2`，带宽 `1/(n·dt)` |
| `redfit` | Schulz & Mudelsee (2002) REDFIT，**调用 easyclimate `filter.redfit.calc_redfit`**（WOSA 分段 + AR(1) 红噪声） | `n50`（分段数，1~32）、`ofac`（过采样）、`hifac`（最高频率倍数）、`iwin`（rectangular/welch/hanning/triangular/blackmanharris）、`mctest`（检验方式）、`nsim`（蒙特卡洛次数） | `dof` / 带宽取自 REDFIT 结果串，缺失时回退 `4n50²/(3n50-1)` 与 `1.21/(seg·dt)` |
| `mtm` | 多窗谱（Thomson 1982），DPSS 锥形窗平均（项目内实现，不依赖 easyclimate） | `nw`（时间带宽积）、`k`（窗数，默认 `min(3, 2nw-1)`） | `dof=2k`，带宽 `2nw/(n·dt)` |

三种方法共用同一套输出，前端切换方法时只需换请求体，渲染逻辑不变。

**REDFIT 的检验方式**（`mctest`）：
- `false`（默认）**红噪声解析检验**：阈值取 REDFIT 输出的 `chi2_80/90/95/99` 列（按 `confidence` 就近选档），只依赖序列本身，不需要额外的时间轴。
- `true` **蒙特卡洛检验**：把真实时间序列作为 `timearray` 传入，REDFIT 对拟合出的 AR(1) 红噪声做 `nsim` 次随机模拟，阈值取 `ci80/ci90/ci95/ci99` 分位列；次数越多阈值越稳、耗时越长（默认 1000）。

若所选参数下 REDFIT 阈值列退化（长度不符 / 含 NaN / 全非正，例如 `n50=1` 且 `ofac>1`），
会自动回退到「AR(1) 理论谱 × 卡方因子」的解析阈值，并在 `meta.threshold_fallback=true` 与前端提示中标注。

`min_periods` / `max_periods` 用于把输出裁剪到关心的周期段（例如 2~200 年），
同时影响绘图范围与峰值提取，不改变谱估计本身。

## 七、关键设计约定

1. **无数据库**：文件即状态。上传文件的元信息存在同目录 sidecar JSON 中，
   列表通过扫描目录重建。优点是零依赖、可直接拷贝；缺点是并发与规模受限。
2. **按请求打开数据集**：`open_dataset` 依赖在请求结束时关闭句柄，避免泄漏；
   代价是同一文件被反复打开（见完善方向中的缓存项）。
3. **算法层与 IO 解耦**：`analysis.py` 只吃一维数组，可脱离 Web 单元测试。
4. **前端零依赖**：不使用 CDN、不需要构建步骤，内网/离线可直接运行。
5. **坐标自动识别**：不强制 CF 规范命名，兼容 `lat/latitude/y`、`lon/longitude/x`、
   `time/date`，并按 `units` 兜底。
6. **显式优于隐式**：指定了不存在的变量直接报 422，不静默换变量。
7. **错误契约**：业务异常统一 `{detail, code}`；4xx 表示用户可修正的问题。
8. **面板与主逻辑解耦**：`parameter_panel.js` 只负责渲染 DOM 与收集输入，
   取数/重算通过 `init()` 注入的回调完成，新增分析时不必改动 `app.js` 的私有函数。
9. **参数单一来源**：所有分析参数的默认值与序列化集中在 `api.js` 的 `state`
   （`preprocessQuery / preprocessBody / spectrumBody`），面板只读写 `state`。

## 八、下一步完善方向

按优先级排列。每条给出「现状 → 问题 → 建议」。

### P0：影响可用性的短板

| # | 方向 | 现状 | 问题 | 建议 |
| --- | --- | --- | --- | --- |
| 1 | **长时间任务异步化** | 分析在请求线程内同步执行 | 大文件 + EEMD/小波 可能数十秒，浏览器超时、无进度 | 引入 `BackgroundTasks` 或 Celery/RQ；改为「提交任务 → 轮询 `/tasks/{id}`」；前端加进度条 |

## 九、附：常见扩展点

### 9.1 新增一个 HTTP 接口

1. 在 `app/api/schemas.py` 定义请求体（如需）。
2. 在对应 `app/api/endpoints/*.py` 写处理函数，签名用 `dataset: NCDataset = Depends(open_dataset)`。
3. 业务逻辑下沉到 `app/services/`，路由里只做参数组装。
4. 在 `static/js/api.js` 加一行封装。
5. 在 `tests/test_api.py` 补用例。

### 9.2 新增一种时序分析

1. 在 `app/services/analysis.py` 写纯函数，入参一维 `values` + 参数，返回可 JSON 化字典。
2. 在 `app/api/schemas.py` 加 `XxxRequest(SeriesRequest)`。
3. 在 `app/api/endpoints/analysis.py` 加路由，复用 `_payload()` 拿到统一前缀。
4. 在 `static/js/analysis_view.js` 加 `renderXxx()` 并注册到 `RENDERERS`。
5. 在 `static/index.html` 菜单里加 `data-tool="xxx"` 按钮，`app.js` 的 `ANALYSIS_CONFIG` 加一项。
6. 若该分析需要参数面板：在 `static/js/parameter_panel.js` 加 `renderXxxPanel / bindXxxPanel`，
   在 `api.js` 的 `state` 里加一份默认值 + `xxxBody()`，由 `analysis_view.js` 调用渲染。

### 9.3 更换配色主题

只改 `static/js/theme.js` 的 `PALETTE` / `SEQUENTIAL` / `DIVERGING` 与
`static/css/style.css` 顶部的 CSS 变量即可，图表与服务端出图各自独立。

### 9.4 接入新的数据源

实现与 `StorageService` 相同接口的类（`list_records / get / path_of / delete`），
或让 `open_dataset` 依赖返回任意 `NCDataset` 兼容对象（如 Zarr、OPeNDAP 远端数据集）。
